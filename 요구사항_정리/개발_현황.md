## ✅ kw_only 호환성 이슈 (해결됨) — 개발 환경은 Python 3.14 사용

`src/nodes/stmt.py`의 모든 Stmt 클래스가 아래처럼 `line` 필드를 선언한다.

```python
line: int = field(default=1, kw_only=True, compare=False)
```

`dataclasses.field()`의 `kw_only` 옵션은 **Python 3.10부터** 지원된다.
`pyproject.toml`에 `requires-python = ">=3.14"`로 이미 명시되어 있는데,
로컬 개발 환경에 Python 3.9.13만 설치되어 있어서 `nodes` 패키지를
import하는 순간 아래 오류로 죽었었다.

```
TypeError: field() got an unexpected keyword argument 'kw_only'
```

**코드나 프로젝트 설정 문제가 아니라 로컬 환경이 프로젝트 요구 버전보다
뒤처져 있던 것이었다.** Python 3.14를 설치해서 해결했고, 3.14 기준으로
전체 테스트(506개) 통과 확인함. 앞으로 이 환경에서 `python`/`pytest`
명령은 3.14를 사용한다 (`py -3.14`로도 명시 가능. 기존 3.9는 그대로
남겨둠).

### class — instanceof만 미완료

| 영역 | 상태 |
| --- | --- |
| 클래스 선언/인스턴스 생성 | 완료 |

### import — Assembler/Checker는 진행, Executor는 미착수

| 영역 | 상태 |
| --- | --- |
| Assembler (문법 파싱, 경로 STRING 제한) | 완료 |
| Checker — 같은 scope 중복 import | 완료 |
| Checker — alias 이름 충돌 | 완료 |
| Checker — 반복문 내부 import | 완료 |
| Checker — **상위 level 중복 import 금지** | **미구현** — import.md 세부 규칙에 명시되어 있으나, 현재 `imported_paths`는 스코프별로만 관리되어 상위 스코프에서 이미 import한 파일을 하위에서 다시 import해도 잡히지 않는다 |
| Checker — import 문법 오류 / 파일 없음 / 순환 import | Assembler 담당으로 분류됨 (미검증, 별도 확인 필요) |
| Executor (파일 읽기/조립/alias로 실제 접근/순환 import 감지) | **미착수** — `src/executor/`에 `ImportStmt` 처리 코드가 전혀 없음 |

## 앞으로 해야 할 일 (우선순위 순)

1. instanceof — Assembler 파싱 추가 (Executor/Node는 이미 있음)
2. import Executor 구현 — 실제 파일 읽기·조립·alias 접근·순환 import 감지
3. import Checker에 "상위 level 중복 import 금지" 규칙 추가
4. 실행전 최적화 착수 (아직 아무도 시작 안 함)
