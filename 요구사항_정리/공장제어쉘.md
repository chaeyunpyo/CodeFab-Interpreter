# [추가] 공장 제어 쉘 구현 항목

## 구현해야 할 모드

| 분류 | 항목 | 설명 | 진입 방법 |
| --- | --- | --- | --- |
| 모드 | 프롬프트 모드 (REPL) | 한 줄씩 입력받아 즉시 실행, 전역 저장소는 세션 동안 유지 | `./factory` |
| 모드 | 파일 모드 | `.txt` 소스 파일을 읽어서 한 번에 실행 | `./factory run <파일경로>` |
| 모드 | 디버그 모드 | Stmt 단위로 멈추며 실행 상태를 점검 | `./factory debug <파일경로>` |

## 구현해야 할 세부 요구사항

| 분류 | 항목 | 설명 |
| --- | --- | --- |
| 프롬프트 모드 | 종료 명령 | `exit` 또는 `quit` 입력 시 종료 |
| 파일 모드 | 파일 없음 처리 | 파일이 존재하지 않으면 명확한 오류 메시지 출력 |
| 파일 모드 | 오류 위치 표시 | 런타임 오류 발생 시 줄 번호와 함께 출력 |
| 파일 모드 | 오류 시 즉시 종료 | 오류 메시지 출력 후 실행을 즉시 종료 |
| 디버그 모드 | stepping 단위 | Stmt 단위로 정지 |
| 디버그 모드 | watch 조회 방식 | 변수 저장소에서 직접 조회해서 출력 |

## 구현해야 할 디버그 명령어 - Stepping

| 명령어 | 설명 |
| --- | --- |
| `step` | 현재 Stmt 실행 후 다음 Stmt에서 정지 |
| `next` | 현재 Stmt 실행 (블록 내부로 진입 X) |
| `break <줄번호>` | 해당 줄에 breakpoint 설정 |
| `breakpoints` | 현재 설정된 breakpoint 목록 출력 |
| `remove <줄번호>` | breakpoint 해제 |
| `continue` | 다음 breakpoint까지 실행 |

## 구현해야 할 디버그 명령어 - Watch Variable

| 명령어 | 설명 |
| --- | --- |
| `watch <변수명>` | 해당 변수를 감시 목록에 추가 |
| `unwatch <변수명>` | 감시 목록에서 제거 |
| `watches` | 현재 감시 중인 변수 목록과 값 출력 (가장 인접한 스코프 기준) |
| `inspect` | 현재 스코프의 모든 변수와 값 출력 |

## 구현해야 할 디버그 명령어 - 기타 (추가)

| 명령어 | 설명 |
| --- | --- |
| `help` | 디버그 모드에서 사용 가능한 명령어 목록과 설명 출력 |
| `version` | 버전 정보(`ErrorZero v1.0`)와 개발자 목록 출력 |

## 적용 가능한 디자인 패턴 (가산점)

> 디자인 패턴은 여러 곳에서 발생될 수 있는 문제를 해결하는 일반화된
> 모범 사례입니다. GoF 디자인 패턴을 사용하면 약간의 추가 점수가
> 주어집니다 (`유의사항.md` 참고).

| 패턴 | 적용 지점 |
| --- | --- |
| Command Pattern | `step`/`next`/`break`/`watch`/`inspect` 같은 디버그 명령어 각각을 "실행 가능한 커맨드 객체"로 만들면, 새 명령어가 추가돼도 명령어 파싱부는 그대로 두고 커맨드 객체만 하나 더 등록하면 된다 (Checker의 `_stmt_handlers`와 같은 확장 방식). |
| State Pattern | 프롬프트/파일/디버그 세 모드를 서로 다른 상태(State)로 두고, 모드별로 입력을 다르게 처리하도록 구성. |
| Strategy Pattern | 파일 모드는 "오류 시 즉시 종료", 디버그 모드는 "오류 시 정지하고 계속 조회 가능" 처럼 오류 처리 방식만 모드별로 다르게 주입. |
